# GitHub Actions workflows are managed by actionspack

This repo uses [`actionspack`](https://github.com/sxzz/actionspack) to pin action versions to commit SHAs. The files under `.github/workflows/*.yaml` are **generated** — the header `# This file is generated by actionspack. Do not edit it manually.` is the canonical signal.

## File layout

- `.github/workflows/src/*.yaml` — source workflows. **Edit these.**
- `.github/workflow.lock.yaml` — lockfile mapping requested versions (`v4`, etc.) to resolved SHAs.
- `.github/workflows/*.yaml` — generated outputs with SHA-pinned `uses:`. **Do not edit.**

## How to change a workflow

1. Edit the source file in `.github/workflows/src/<name>.yaml`.
2. Regenerate and refresh the lockfile:
   ```sh
   pnpm dlx actionspack
   ```
3. Commit the source, the regenerated workflow, and the updated `workflow.lock.yaml` together.

## Other actionspack commands

- `pnpm dlx actionspack update [package]` — bump locked SHAs (all packages, or one).
- `pnpm dlx actionspack verify` — fail-fast check that outputs match the lockfile (good for CI).
- `pnpm dlx actionspack diff` — show lockfile changes vs HEAD.
- `pnpm dlx actionspack tree` / `why <package>` — inspect the dependency graph.

If you find yourself wanting to edit a generated `.github/workflows/*.yaml` directly, stop and edit the corresponding `src/` file instead.
